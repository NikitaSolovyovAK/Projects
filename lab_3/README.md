# Pong

Аркадная игра Pong на Python с использованием библиотеки pygame. Реализованы игра против бота и онлайн-режим на двоих по сети. Есть меню, таблица рекордов, справка, звук и музыка, анимации.

Лабораторная работа №3 по курсу «Проектирование программного обеспечения интеллектуальных систем» (часть 2). Вариант 13 — Pong (игра с ботом и онлайн-игра на двоих).

## Об игре

Pong — классическая аркада: две ракетки и мяч. Игрок управляет левой ракеткой, отбивая мяч. Если мяч вылетает за правую границу поля — очко игроку, за левую — очко сопернику. Матч идёт до заданного числа очков.

Игра поддерживает два режима:

- **Против бота** — правой ракеткой управляет простой ИИ, который следит за мячом.
- **Онлайн на двоих** — два игрока подключаются к серверу по сети, каждому назначается сторона (левая или правая).

## Возможности

- Главное меню: начать игру, таблица рекордов, справка, выход
- Экран справки с правилами и описанием управления
- Игра против бота с настраиваемой сложностью
- Сетевой режим на двух игроков (клиент-сервер, TCP)
- Таблица рекордов с сохранением между запусками
- Диалог ввода имени при установке нового рекорда
- Фоновая музыка и звуковые эффекты
- Анимации: след за мячом, вспышка при ударе, всплывающий текст при голе

## Управление

- **W** или **стрелка вверх** — движение ракетки вверх
- **S** или **стрелка вниз** — движение ракетки вниз
- **Стрелки** и **Enter** — навигация по меню
- **Esc** — назад в меню / выход

## Событийно-ориентированная архитектура

В основе приложения лежит игровой цикл и обработка событий pygame. На каждой итерации цикл:

1. считывает события (нажатия клавиш, закрытие окна) и реагирует на них;
2. обновляет состояние игры (движение мяча и ракеток, логика бота);
3. перерисовывает экран.

Поведение игры разделено на состояния (`states.py`): меню, игра, справка, таблица рекордов, экран окончания, ввод имени, подключение к серверу и онлайн-игра. Текущее состояние определяет, какие события обрабатываются и какой экран рисуется. Переходы между состояниями происходят в ответ на действия пользователя. Такой подход отделяет реакцию на события от отрисовки и упрощает добавление новых экранов.

За визуальную часть отвечает класс `GameUI` — он рисует каждый экран, но не содержит игровой логики. Игровые объекты `Ball`, `Paddle` и `BotController` инкапсулируют собственное поведение.

## Онлайн-режим

Сетевой режим реализован по схеме клиент-сервер поверх TCP.

**Сервер** (`server.py`) принимает до двух игроков, назначает каждому роль (левый/правый), ведёт единое состояние игры (позиции мяча и ракеток, счёт) и рассылает его обоим клиентам. Приём подключений, обработка сообщений от клиентов и игровой цикл выполняются в отдельных потоках. Пока не подключились оба игрока, игра находится в состоянии ожидания.

**Клиент** (`client.py`) подключается к серверу, в отдельном потоке принимает обновления состояния и отправляет команды управления (вверх/вниз/стоп). Полученное состояние отрисовывается на экране игрока.

**Протокол** (`protocol.py`) — обмен сообщениями в формате JSON, разделённых переносом строки. Это позволяет корректно собирать сообщения из потока данных, даже если они приходят частями.

## Конфигурация

Настройки приложения (характеристики мяча и ракеток, пути к звукам и музыке, параметры игры) хранятся во внешних файлах формата JSON в папке `config`, а не зашиты в код. Это позволяет менять поведение и оформление игры без правки исходников.

## Таблица рекордов

Рекорды хранятся в JSON-файле в папке `data` и загружаются при запуске. Хранятся имя игрока и его счёт; список отсортирован по убыванию и ограничен десятью лучшими результатами. Если по завершении матча результат игрока превышает лучший в таблице, показывается диалог с поздравлением и полем для ввода имени, после чего рекорд сохраняется.

## Анимации и звук

**Анимации** реализованы покадрово в игровом цикле:
- след за мячом — короткая цепочка уменьшающихся прямоугольников за его траекторией;
- вспышка при ударе — быстро исчезающий круг вокруг мяча в момент отбивания;
- всплывающий текст при голе с постепенным затуханием.

**Звук** управляется классом `SoundManager`: он загружает эффекты и фоновую музыку из конфигурации. Если звуковое устройство недоступно, игра продолжает работать без звука, не завершаясь с ошибкой.

## Установка и запуск

Требуется Python 3.10+ и pygame.

```bash
pip install -r requirements.txt
python main.py
```

Для онлайн-режима сначала запустите сервер:

```bash
python -m network.server
```

Затем подключитесь к нему из игры на двух устройствах (или в двух копиях приложения), выбрав онлайн-режим в меню. По умолчанию сервер слушает порт 5000.
