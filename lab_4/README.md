## Идея работы

В основе лежит одна и та же модель файловой системы: диски, папки, файлы, пользователи и права доступа. Поверх этой модели работают два независимых интерфейса:

- **CLI** — консольный интерфейс из ЛР №1.
- **Веб-интерфейс** — клиент-серверное приложение на Flask (эта работа).

Оба интерфейса используют один и тот же слой бизнес-логики и вызывают одни и те же операции. Это демонстрирует главное требование работы: общий код выделен и переиспользуется, а интерфейс — лишь тонкая надстройка над моделью.

## Общий код CLI и веб-интерфейса

Разделяемая часть не зависит от способа взаимодействия с пользователем:

- `core/filesystem.py` — ядро: пользователи, диски, разрешение путей, загрузка и сохранение состояния.
- `models/` — сущности предметной области (файл, папка, диск, пользователь, права, формат).
- `operations/` — операции над моделью (создание, копирование, удаление, перемещение, права, архивирование, резервное копирование, организация).

CLI и веб-приложение вызывают одни и те же функции из `operations`, поэтому поведение системы одинаково в обоих режимах. Веб-слой (`web/app.py`) только принимает HTTP-запросы, вызывает нужную операцию и возвращает результат — собственной бизнес-логики он не содержит.

Запуск режима выбирается флагом командной строки, что наглядно показывает работоспособность обоих интерфейсов на общем коде:

```bash
python main.py            # CLI
python main.py --web      # веб-интерфейс
```

## Возможности веб-интерфейса

Веб-интерфейс предоставляет все возможности управления моделью из ЛР №1 и отображение её текущего состояния:

- Просмотр содержимого текущей папки и навигация по дереву каталогов
- Отображение состояния диска: общий объём, занято, свободно
- Создание файлов и папок
- Чтение и запись содержимого файлов
- Копирование, перемещение и удаление
- Управление правами доступа и владельцем
- Архивирование и распаковка
- Резервное копирование и восстановление
- Автоматическая организация файлов по категориям

Каждое действие изменяет модель и сразу сохраняет состояние, поэтому изменения не теряются между запросами.

## Архитектура клиент-сервер

Приложение построено по клиент-серверной схеме поверх протокола HTTP.

**Сервер** (Flask) хранит состояние модели и предоставляет два вида точек входа:
- страницу интерфейса (`/`), которая отдаёт HTML;
- набор HTTP API-эндпоинтов (`/api/...`), которые принимают и возвращают данные в формате JSON.

**Клиент** — браузер. Он загружает страницу, а затем обменивается с сервером данными через API: отправляет запросы на выполнение операций и получает обновлённое состояние модели, обновляя отображение без перезагрузки страницы.

Такое разделение соответствует классической модели: сервер отвечает за данные и логику, клиент — за отображение и взаимодействие с пользователем. Обмен идёт по HTTP: GET для получения состояния, POST для операций, изменяющих модель.

## HTTP API

Сервер предоставляет REST-подобные эндпоинты. Получение состояния — методом GET, изменяющие операции — методом POST с параметрами в теле запроса в формате JSON. Ответы также приходят в JSON: при успехе — статус и сообщение, при ошибке — статус ошибки и её описание.

| Метод | Путь | Назначение |
|-------|------|------------|
| GET  | `/api/state`    | Текущее состояние: путь, содержимое, дерево, данные о диске |
| POST | `/api/cd`       | Перейти в папку |
| POST | `/api/touch`    | Создать файл |
| POST | `/api/mkdir`    | Создать папку |
| POST | `/api/write`    | Записать содержимое в файл |
| POST | `/api/cat`      | Прочитать содержимое файла |
| POST | `/api/cp`       | Копировать |
| POST | `/api/mv`       | Переместить или переименовать |
| POST | `/api/rm`       | Удалить (с опцией рекурсии) |
| POST | `/api/chmod`    | Изменить права доступа |
| POST | `/api/chown`    | Сменить владельца |
| POST | `/api/archive`  | Заархивировать файлы |
| POST | `/api/extract`  | Распаковать архив |
| POST | `/api/backup`   | Создать резервную копию |
| POST | `/api/restore`  | Восстановить из копии |
| POST | `/api/organize` | Организовать файлы по категориям |

## Установка и запуск

Требуется Python 3.10+. Зависимости веб-части (Flask) устанавливаются из файла зависимостей.

```bash
pip install -r requirements.txt
```

Запуск веб-интерфейса:

```bash
python main.py --web
```

После запуска откройте в браузере адрес, указанный в консоли (по умолчанию `http://127.0.0.1:5000`). Порт можно задать флагом:

```bash
python main.py --web --port=8080
```

Запуск консольного интерфейса на том же общем коде:

```bash
python main.py
```

При первом запуске создаётся начальная конфигурация: пользователь `admin`, диск `C:` и корневая папка. Состояние сохраняется в `data/state.json`.

## Модель прав доступа

Права заданы в восьмеричной системе по образцу Unix. Для каждой из трёх категорий (владелец, группа, остальные) действует комбинация трёх флагов: чтение (r, 4), запись (w, 2), выполнение или вход в папку (x, 1). Например, режим `755` означает `rwxr-xr-x`. Менять права может владелец элемента или пользователь `admin`; менять владельца — только `admin`. Логика прав общая для CLI и веб-интерфейса.
