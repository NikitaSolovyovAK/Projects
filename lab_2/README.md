# Расписание поездов

Оконное приложение для ведения расписания поездов: добавление записей через диалоги, поиск и удаление по разным условиям, постраничный вывод, хранение в базе данных SQLite и обмен данными через XML. Построено по шаблону Model-View-Controller.

Лабораторная работа №2 по курсу «Проектирование программного обеспечения интеллектуальных систем» (часть 2). Вариант 13.

## Предметная область

Каждая запись описывает один поезд: его номер, станции отправления и прибытия, дату и время отправления и прибытия. Время в пути не вводится вручную, а вычисляется автоматически как разница между прибытием и отправлением.

Поля записи (вариант 13):

| Поле | Тип | Примечание |
|------|-----|------------|
| Номер поезда | строка | не может быть пустым |
| Станция отправления | строка | не совпадает со станцией прибытия |
| Станция прибытия | строка | не совпадает со станцией отправления |
| Дата и время отправления | дата/время | вводится через календарь |
| Дата и время прибытия | дата/время | должно быть позже отправления |
| Время в пути | вычисляется | не вводится вручную |

## Возможности

- Добавление записей через диалоговое окно с проверкой корректности данных
- Поиск записей по четырём разным условиям в отдельном диалоге; результат выводится там же
- Удаление записей по условиям в отдельном диалоге, с сообщением о количестве удалённых записей
- Отображение всех записей в главном окне в виде таблицы
- Альтернативное отображение записей в виде дерева, где листья — отдельные поля записи
- Постраничный вывод в главном окне и в диалоге поиска
- Хранение записей в базе данных SQLite
- Сохранение и загрузка данных в формате XML
- Выбор и сохранение файла базы данных через стандартные диалоги открытия/сохранения

## Архитектура (MVC)

Приложение разделено на три слоя, что соответствует шаблону Model-View-Controller.

**Model** — данные и бизнес-логика, не зависящие от интерфейса:
- `TrainRecord` — модель записи с валидацией и вычислением времени в пути.
- `search_criteria` — классы условий поиска и удаления.
- Репозитории и сервисы (хранение, поиск, пагинация, импорт/экспорт XML).

**View** — окна и диалоги на PySide6. Они только отображают данные и посылают сигналы о действиях пользователя, не содержат бизнес-логики:
- `MainWindow`, `AddTrainDialog`, `SearchDialog`, `DeleteDialog`, `PaginationWidget`.

**Controller** — `MainController` связывает представление и модель: подписывается на сигналы окон, вызывает нужные сервисы и репозиторий, обновляет отображение.

Такое разделение делает модель пассивной: она ничего не знает о представлении, а контроллер выступает посредником. Взаимодействие между слоями построено на механизме сигналов и слотов Qt.

Репозиторий описан через абстрактный класс `TrainRepository`, а конкретная реализация `SQLiteTrainRepository` подставляется при запуске. Это позволяет заменить способ хранения, не меняя контроллер.

## Модель записи

`TrainRecord` при создании проверяет данные и выбрасывает `TrainValidationError`, если:

- любое из текстовых полей пустое;
- станции отправления и прибытия совпадают;
- время прибытия не позже времени отправления.

Время в пути хранится как `timedelta` и вычисляется в конструкторе. Для отображения оно форматируется как «N ч M мин». Модель также содержит методы сопоставления с условиями поиска (по номеру, дате, станциям, попаданию времени в диапазон, времени в пути).

## Условия поиска и удаления

Поиск и удаление используют одни и те же условия, но в разных диалогах. Доступны четыре режима:

1. **По номеру поезда или дате отправления.** Можно задать номер, дату или и то, и другое.
2. **По диапазону времени отправления или прибытия.** Задаётся нижняя и верхняя граница; поддерживается интервал, переходящий через полночь.
3. **По станции отправления или прибытия.**
4. **По времени в пути.** Задаётся точная длительность (часы и минуты).

В диалоге выбор режима переключает набор полей ввода. Перед выполнением условия проверяются на заполненность. При удалении приложение сообщает, сколько записей было удалено, а если подходящих не нашлось — выводит соответствующее сообщение.

## Хранение данных

**База данных.** Записи хранятся в SQLite. При запуске файл базы создаётся автоматически в папке `data`. Даты и время хранятся в формате ISO, время в пути в минутах — целым числом. Через меню можно открыть другую базу или сохранить текущую под новым именем.

**XML.** Обмен файлами реализован в формате XML согласно требованиям:
- запись в файл — через DOM-парсер (`xml.dom.minidom`);
- чтение из файла — через SAX-парсер (`xml.sax`).

При загрузке XML данные помещаются в базу, заменяя текущее содержимое.

## Установка и запуск

Требуется Python 3.10+ и библиотека PySide6.

```bash
pip install PySide6
python -m train_schedule_app.app
```

Либо запустите `app.py` напрямую из среды разработки. База данных создаётся при первом запуске.

## Работа с приложением

Команды доступны через меню и продублированы на панели инструментов.

- **Записи → Добавить** — открыть диалог добавления новой записи.
- **Записи → Поиск** — открыть диалог поиска; результаты выводятся в том же окне постранично.
- **Записи → Удаление** — открыть диалог удаления по условиям.
- **Файл → Сохранить XML / Загрузить XML** — обмен данными через XML-файл.
- **Файл → Открыть БД / Сохранить БД как** — работа с файлами базы данных.

В главном окне записи показаны на двух вкладках: «Таблица» и «Дерево». Внизу расположен виджет постраничного вывода: переход на первую, предыдущую, следующую и последнюю страницы, выбор числа записей на странице, номер текущей страницы, общее число страниц и записей.

## Демонстрационные данные

В папке `demo_xml` находятся XML-файлы с готовыми наборами записей (не менее 50 осмысленных записей в каждом) для демонстрации загрузки и работы приложения.
